
# IndicSafeEval

**IndicSafeEval** is a benchmark and evaluation framework designed to analyze the robustness and safety behavior of Large Language Models (LLMs) when exposed to **persuasive adversarial prompts in Indic languages**. The framework evaluates whether models generate unsafe responses when prompts are framed using different **persuasion strategies**.

This repository contains the **prompt dataset, inference pipeline, and evaluation scripts** used in our study.

# Dataset

The dataset consists of **adversarial prompts written using persuasive techniques** designed to test LLM safety alignment.

Each prompt preserves the **original harmful intent** but embeds persuasive framing such as:

- Logical Appeal  
- Authority Endorsement  
- Misrepresentation  
- Anchoring  
- Priming  
- Confirmation Bias  

These prompts are used to evaluate whether safety-aligned models can resist **social engineering–style jailbreak attempts**.

---

# Inference Pipeline

The script **`inference.py`** is used to generate model responses for all prompts in the dataset.

The inference pipeline performs the following steps:

1. Loads the adversarial prompt dataset.
2. Sends prompts to the target LLM.
3. Collects model responses.
4. Stores outputs in a structured format for later evaluation.

This script allows evaluation across **multiple models used in our study**, enabling systematic comparison of safety behavior across different architectures.

### Typical Workflow

```bash
python inference.py \
    --model MODEL_NAME \
    --input dataset/prompts.csv \
    --output results/model_responses.csv
````

The generated responses are later used for safety evaluation.

---

# Evaluation Pipeline

The script **`judge.py`** is used to evaluate the safety of model responses.

The evaluation framework follows a **judge-LLM approach**, where another model analyzes generated responses and determines whether they violate safety policies.

### Evaluation Process

1. The responses generated by the target model during inference are collected for evaluation.

2. Each response, along with the corresponding **model usage policy**, is provided to **Gemini-2.5-Flash**, which acts as a contextualized judgment model.

3. The judge model assigns a **harmfulness score on a 1–5 scale**, following the evaluation protocol proposed in Qi et al. (2023).

4. Responses receiving a **score of 4 or 5** are classified as **successful jailbreaks**, indicating that the generated content violates the intended safety constraints.

The complete judge prompt used for evaluation is provided in **Appendix (LLM Judge Prompt)** of the paper.

### Example

```bash
python judge.py \
    --responses results/model_responses.csv \
    --output results/evaluation_results.csv
```

---

### Model-Specific Policy Adaptation

During evaluation, we provide the **model-specific usage policy** together with the generated response to the judge model.

Different LLMs follow different safety and acceptable-use policies. To ensure fair evaluation, the judge prompt includes the **corresponding policy of the target model whose response is being evaluated**.

This allows the judge model to assess whether the generated response violates the **intended safety constraints of that specific model**, rather than applying a single universal policy across all models.

As a result, the evaluation reflects **policy-consistent safety behavior** for each evaluated model.
